## 2. Only the owner can do these, roughly in this order

1. **Apple Developer Program** membership, then a **bundle ID** `jibaro.spacepirate.love` (same as
   Android's package) and an **app record** in App Store Connect. Billing (B6) also waits on this.
2. **Signing:** set the development team in the project (`DEVELOPMENT_TEAM`, `CODE_SIGN_STYLE =
   Automatic`), then Product → Archive in Xcode and upload. Signing settings are not in this repo yet
   on purpose.
3. **Broker login for release builds. Must fix before any upload.** `Config/Secrets.xcconfig` is
   generated by `scripts/make-secrets.sh` from this Mac's Keychain entry `FamilySafety-MQTT`, which
   holds the **separate test account** used by the test harness, not the one Android ships with
   (`keystore/mqtt.properties` on the Android side). A release built today connects as the test user.
   Decide which login iOS should use, put it in the Keychain entry (or point the script at another
   entry), and rebuild.
4. **Export compliance** (section 3). Once decided, add `INFOPLIST_KEY_ITSAppUsesNonExemptEncryption`
   to the build settings so App Store Connect stops asking on every build.
5. **Privacy policy:** it describes Android only. It names OpenStreetMap tiles and the OSRM
   drive-time server; the iPhone uses neither. The iPhone's maps come from Apple (MapKit) and it has
   no drive-time feature. Add an iOS paragraph and republish `docs/privacy.html`.
6. **App Privacy answers** in App Store Connect (section 4), **age rating** questionnaire (the app
   has chat between family members and shares location), **support URL** (the project site
   `https://singularity86.github.io/FamilySafety/` would do), category, and the listing (section 5).
7. **Screenshots at Apple's required size** (section 6).

## 3. Export compliance: the facts to answer from

The app uses encryption **for the confidentiality of user content**, not only for authentication,
so it is not covered by the "authentication only" exemption. Everything is standard, published
algorithms through libsodium and Apple's CryptoKit; nothing proprietary.

| Use | Algorithm | Code |
|---|---|---|
| Messages between phones (location, chat, roster, files' control messages) | X25519 + XSalsa20-Poly1305 (`crypto_box`), Ed25519 signatures | `FamilySafetyCore/SodiumCrypto.swift`, `Envelope/` |
| Shared files, vault, local storage | AES-256-GCM (CryptoKit) | `Files/FileCodec.swift`, `Vault/VaultSlots.swift`, `Storage/SealedFileSlot.swift` |
| Keys from the recovery phrase and vault code | BIP-39 / SLIP-10 (HMAC-SHA512), Argon2id | `Bip39.swift`, `Slip10.swift`, `Vault/VaultSlots.swift` |
| Join requests | HMAC-SHA256 | `Onboarding/JoinV2.swift` |
| Transport | TLS, from the system | `Transport/` |

It is a free consumer app available to the public (a "mass market" item under the US EAR, as far as
these facts go). **Whether that makes it exempt, and whether a self-classification report or the
French declaration is needed, is a legal answer for the owner.** Apple's export compliance page and
the BIS encryption pages are the sources to read.

## 4. App Privacy answers (draft, confirm against Apple's definitions)

Apple counts data as **collected** when it leaves the device in a way that lets the developer or
partners read it beyond what the request needs in real time. On that reading:

| Data | Collected? | Why |
|---|---|---|
| Precise location, chat, files, vault documents, names and colours | **No** | End-to-end encrypted between family phones. The relay stores ciphertext it can't open; the developer holds no keys. |
| User ID (the member ID, a hash of the phone's public key) | **Yes**: not linked to identity, not used for tracking, app functionality | The relay sees it in topic names and in the plaintext presence it keeps (online/offline). Matches `PrivacyInfo.xcprivacy`. |
| IP address | Not as "collected" data, provided the relay (EMQX Cloud) keeps no IP logs beyond operating the connection. **Check the EMQX account's log settings.** | |
| Purchases | Revisit when billing (B6) lands. | |
| Diagnostics, analytics, ads | **No.** None in the app; no third-party SDKs that collect. | |

"Data used to track you": **none**. Accounts: there are none to delete; "Leave family" erases the
family keys from the phone, and the recovery phrase never leaves it.
